# D.UNI Programmer v0.1 — програма для ПК

Програма для роботи з флешем мікроконтролерів через **D.UNI Probe** (прошивка v1.1).
Аналог базових функцій STM32CubeProgrammer, але для всіх контролерів, які підтримує D.UNI.

## Запуск
1. Встановіть **Python 3.10+** з https://www.python.org/downloads/ (галочка *Add python.exe to PATH*).
2. Двічі клікніть **`run.bat`**. Перший запуск 1–3 хв: створюється папка `.venv` і встановлюються
   бібліотеки (pyOCD, esptool). Далі програма стартує одразу.
3. `update_libs.bat` — оновити бібліотеки.

## Можливості
| | ARM / SWD (STM32, RP2040, інші Cortex-M) | ESP32 / ESP8266 (UART) |
|---|---|---|
| Пошук пристрою | список CMSIS-DAP пробників | список COM-портів, порт D.UNI позначено |
| Підключення / інформація | DP IDR, CPUID (ядро), STM32 DEV_ID + розмір флешу, RP2040 CHIP_ID | тип чипа, MAC, ID і розмір флешу |
| Карта пам'яті | так (FLASH/RAM регіони) | — |
| Запис .bin/.hex/.elf | так, з вибором стирання (auto/sector/chip) | до 4 файлів .bin за адресами |
| Verify | так (порівняння з читанням) | так (MD5) |
| Читання → HEX-перегляд / файл .bin/.hex | так | у файл .bin |
| Стирання: весь чип / діапазон | так | так |
| Перевірка на чистоту (blank check) | так | — |
| Reset / Reset+Halt / Halt / Run | так | автоматичний reset після запису |
| Connect under reset | режим `under-reset` (потрібен провід NRST -> GP1) | — |

### Вибір цілі (ARM)
- Вбудовані в pyOCD: `rp2040`, `stm32f103rc`, `stm32f051`, `stm32f412xx`, `stm32f429xx`, `stm32l432kc`, `stm32h7xx` тощо.
- **STM32F103C8/CB (Blue Pill)** — можна обрати `stm32f103rc` (той самий алгоритм флешу), або встановити точний pack.
- Будь-який інший STM32: введіть назву (напр. `stm32g030f6`, `stm32f401cc`) у поле **Pack** -> **Встановити**.
  Перший раз завантажується індекс CMSIS-Pack з інтернету (кілька хвилин), далі ціль з'являється у списку.

### Поради
- Якщо не підключається: знизьте частоту до 1 MHz/100 kHz, перевірте GND, спробуйте режим `under-reset`.
- STM32 з увімкненим захистом читання (RDP level 1) — читання поверне помилку; зняття RDP буде в наступній версії.
- Налаштування зберігаються в `duni_settings.json`.

## Структура
```
duni_programmer.py      вікно програми (tkinter)
duni/arm_backend.py     ARM/SWD операції (pyOCD, CMSIS-DAP)
duni/esp_backend.py     ESP операції (esptool через UART-міст)
duni/fileutil.py        .bin/.hex/.elf, hexdump
```
Backend-модулі не залежать від вікна — їх можна викликати з веб-сервера (див. нижче).

## Майбутнє: керування через сайт
Так, це можливо. Два шляхи:

**A. Браузер напряму до пристрою (рекомендовано).** Chrome/Edge мають WebUSB і WebSerial:
- CMSIS-DAP v2 (SWD) — бібліотека **DAPjs** (Arm), працює в браузері через WebUSB;
- ESP32 — **esptool-js** (Espressif) через WebSerial.
Ваш сервер віддає сторінку, нічого встановлювати не треба. Нові контролери та нова прошивка
пробника (UF2) додаються на сервері — користувач просто оновлює сторінку. Потрібно додати в прошивку
D.UNI WebUSB-дескриптор (невелика зміна).

**B. Локальний агент.** Маленька програма на ПК (ці ж backend-модулі на Python) тримає WebSocket-з'єднання
з сервером і виконує команди. Дозволяє віддалену роботу (пристрій в одному місці, оператор в іншому).

Обидва варіанти можна поєднати; рекомендований порядок: зараз Python-програма -> агент (B) -> WebUSB (A).
